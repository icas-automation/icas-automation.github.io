# Configuration Parameters

The module offers extensive customization options to tailor its operation to individual user needs, installation characteristics, and desired results.

After a successful installation, the module assumes a default configuration that ensures basic and safe operation. However, the user can modify individual parameters at any time.

The following sections provide a detailed overview of each parameter, including basic information, impact on system operation, as well as tips and recommendations.

## How to Read Parameter Descriptions
This section describes the properties included in the initialization parameter descriptions.

| Property | Description |
| :--- | :--- |
| **Parameter type** | Specifies the parameter type:<ul><li>**Boolean**: accepts `true` or `false` as a value.</li><li>**String**: accepts any sequence of characters as a value, following the syntax specified for the given parameter.</li><li>**Integer**: accepts a numerical value.</li></ul> |
| **Default value** | Specifies the value assumed by the parameter if a value is not explicitly provided. |
| **Editable** | Specifies whether the parameter can be edited: a value of `true` means the parameter can be modified by the user, while `false` indicates that the value is managed exclusively by the system. |
| **Value range** | Specifies the allowable range of values for this parameter, presented as a minimum and maximum value or a list of values. This property does not apply to all parameters. |

## How to Change Parameter Values in the Fibaro Interface
Parameter modification is carried out through the standard user interface of the Fibaro controller (Home Center 3 / Yubii Home) in the section dedicated to device variables. To make changes, follow these steps:
1. Log in to the **Fibaro** administration panel.
2. Go to the **Devices** tab in the side menu.
3. Find and open the device from the list.
4. Go to the **Variables** tab at the top of the device view.
5. Locate the variable corresponding to the parameter you want to change.
6. Enter the new value in the text field next to the variable.
7. Save changes by clicking the **Save** button.

::: info TIP
Before making changes, ensure that the entered values comply with the allowable range for the given parameter. Incorrect values may affect the proper operation of the module.
:::

## CONFIG_STATUS
The `CONFIG_STATUS` parameter defines the current configuration status of the module or allows restoring its default settings.

| Property | Description |
| :--- | :--- |
| **Parameter type** | String |
| **Default value** | `INITIALIZED` |
| **Editable** | `true` |
| **Value range** | INITIALIZED, RESET |

::: danger WARNING
Setting the value to `RESET` will permanently delete the current configuration and historical data of the module, and then restore factory settings.
:::

## LANGUAGE
The `LANGUAGE` parameter defines the language of the interface and messages generated by the module.

| Property | Description |
| :--- | :--- |
| **Parameter type** | String |
| **Default value** | `AUTO` |
| **Editable** | `true` |
| **Value range** | AR, CS, DA, DE, EN, ES, ET, FI, FR, HU, IT, JA, KA, LT, NL, NO, PL, PT, RO, RU, SL, SV, TR, ZH, AUTO |

::: info TIP
Setting the value to `AUTO` will force reading the language from the FIBARO interface and set it as current, provided it is supported.
:::

## MIN_IDLE_TIME
The `MIN_IDLE_TIME` parameter specifies the minimum time (in seconds) that overproduction must remain positive before the device is started. This aims to prevent accidental device activation due to short-term overproduction spikes.

| Property | Description |
| :--- | :--- |
| **Parameter type** | Integer |
| **Default value** | `300` |
| **Editable** | `true` |
| **Value range** | Greater than 30 |

## MIN_RUN_TIME
The `MIN_RUN_TIME` parameter specifies the minimum operating time of the device (in seconds) after being switched on, regardless of overproduction availability. This prevents too frequent switching, protecting components from damage.

| Property | Description |
| :--- | :--- |
| **Parameter type** | Integer |
| **Default value** | `1200` |
| **Editable** | `true` |
| **Value range** | Greater than 30 |

::: danger IMPORTANT
The value of this parameter must be adjusted with great care to avoid damaging device components. Below is a list of the most popular devices alongside suggested minimum run times:
<ul>
<li><b>Boiler / Electric Water Heater</b>: 30–60 minutes (1800–3600 s). Water needs time to noticeably increase its temperature. Frequent activation for 2–3 minutes only wears out the relay contact without providing a real heating effect.</li>
<li><b>Heat Pump (DHW / Space Heating)</b>: 30–45 minutes (1800–2700 s). Highly critical! Compressors in heat pumps and air conditioners tolerate short cycling very poorly. Too frequent starts drastically shorten device lifespan.</li>
<li><b>Air Conditioning (Cooling/Heating)</b>: 20–30 minutes (1200–1800 s). Similar to heat pumps—refrigerant needs several minutes to stabilize pressure and circulation after compressor startup.</li>
<li><b>Pool Pump / Filtration</b>: 30–60 minutes (1800–3600 s). Water circulation in a pool is effective only when running for longer periods. Additionally, induction pump motors consume the most power during initial startup.</li>
<li><b>EV Charger (Electric Vehicle)</b>: 15–30 minutes (900–1800 s). EV battery packs and Battery Management Systems (BMS) require a few to several seconds to negotiate charging current. Continuous interruption and resumption of charging can cause on-board computer errors.</li>
<li><b>Dishwasher / Washing Machine / Dryer</b>: Full cycle duration (e.g., 60–120 min). If the device does not have a pause function, cutting power mid-program will cause an error or reset the cycle from the beginning.</li>
<li><b>Electric Heater / Fan Heater</b>: 10–15 minutes (600–900 s). Heaters (especially oil-filled ones) have high thermal inertia. Short cycles won't allow effective room heating.</li>
<li><b>Dehumidifier / Humidifier</b>: 15–20 minutes (900–1200 s). Allows surrounding humidity levels to stabilize and avoids frequent dehumidifier compressor cycling.</li>
<li><b>Garden / Decorative Lighting</b>: 5–10 minutes (300–600 s). Ensures aesthetics (avoids a "flickering" garden effect when clouds obscure the sun).</li>
</ul>
:::

## POWER_ON_RULE
The `POWER_ON_RULE` parameter defines a logic condition that must be met for the device to start (e.g., temperature below 55°C). The parameter value is a logical expression based on `[ID:property]` syntax, which the system evaluates in real time.

Example:
`[123:value] > 55 and [234:value] < 0`

| Property | Description |
| :--- | :--- |
| **Parameter type** | String |
| **Default value** | `TRUE` |
| **Editable** | `true` |

| Property | Description |

| **Default value** | 0 (no device specified) |
| **Editable** | `true` |
| **Value range** | Greater than 0 |

## SWITCH_PWR
The `SWITCH_PWR` parameter defines the power consumption of the device (in Watts) during normal operation.

| Property | Description |
| :--- | :--- |
| **Parameter type** | Integer |
| **Default value** | `AUTO` |
| **Editable** | `true` |
| **Value range** | Greater than 0 or `AUTO` |

::: info TIP
Setting the value to `AUTO` forces an automatic read of the required power from the device. If reading is not possible, the system will return an error and prompt for manual power entry.
:::

## SWITCH_PWR_THLD
The `SWITCH_PWR_THLD` parameter defines the percentage threshold of device power that must be covered by solar overproduction for the device to turn on. The default value of 100% means the device will only start when overproduction fully covers the power defined in `SWITCH_PWR`.

| Property | Description |
| :--- | :--- |
| **Parameter type** | Integer |
| **Default value** | `100` |
| **Editable** | `true` |
| **Value range** | Greater than 0 |

::: info TIP
For smaller installations with low overproduction, lowering this parameter (e.g., to 50%) is recommended. The device will turn on when solar energy covers at least half of the required power—the rest will be pulled from the grid, maximizing local energy usage.

If you have a large installation with multiple devices competing for power, it is better to leave the value at 100% or higher.
:::
